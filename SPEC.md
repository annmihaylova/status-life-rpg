## 1. Зачем это всё

Пользователь делает много полезного, но не в формате «задача → галочка», как в Habitica: лекции, чтение статей, проекты, репетиторство, разборы с ИИ. Всё это идёт потоком, часто параллельно. Из-за этого возникает ощущение, что ты «никуда не двигаешься», хотя на деле прогресс огромный — просто его не видно.

**Главная цель продукта — сделать накопленный прогресс видимым.** Это не таск-менеджер и не инструмент давления.

Отсюда принципы:

- **Никаких наказаний.** Нет потери HP, нет сгорания стриков, нет «смерти персонажа». XP и уровни только растут. Пропущенный день — просто пустой день.
- **Отдых тоже важен.** Сон, хобби и прогулки восстанавливают HP (2.6), а день отдыха даёт бафф «Восстановление», чтобы приложение не толкало к выгоранию.
- **Честное время, а не время по часам.** Если чат по проекту шёл с 10:00 до 15:00, но параллельно была 2-часовая лекция, проект получает ~1.5–2 часа, а не 5. Считается фокусное время, которое оценил сам человек.
- **ИИ предлагает — человек подтверждает.** Всё, что пришло от ИИ, сначала черновик. Подтверждение — один тап.
- **Минимум трения.** Вечерний отчёт голосом за 1–2 минуты. Правка черновиков — свайпы и тапы, без форм.
- **Приватность.** Журнал активности — это личные данные. Шифрование при передаче, Row Level Security, экспорт и полное удаление аккаунта.

## 2. Игровая модель

### 2.1 Три слоя прогресса и HP

Главное правило: **три слоя растут с разной скоростью**, как в LitRPG.

| Слой | Что это | Скорость | Откуда растёт |
|---|---|---|---|
| **Уровень персонажа** | общий прогресс | быстро в начале, потом медленнее | любая подтверждённая активность |
| **Навыки** | обобщённые умения уровня «Биология», «Программирование», «Кулинария», «Вождение» | быстро, уровни до 100+ | активность в этом навыке |
| **Характеристики** | 3 общие (Тело, Разум, Дух), которые со временем **могут** раскрыться в 9 конкретных | **редко**: звезда — событие, +1 очко — праздник | оценка на старте + XP навыков по тегам при долгом использовании |

Отдельно — **HP (Здоровье)**: полоска текущего состояния у каждого персонажа (2.6).

```
Activity entry
   ├─ → XP персонажа (всегда)
   ├─ → XP навыка (взятого, спящего или кандидата, 2.2)
   └─ → XP характеристик: через теги навыка (основная 2/3, вторичная 1/3)
Сон, отдых, самочувствие, перегруз → HP
```

### 2.2 Навыки: обобщённые, как у Атаманова

Ориентир по обобщённости — навыки из книг Михаила Атаманова («Тёмный травник», «Искажающие реальность»): «Алхимия», «Торговля», «Кулинар», «Атлетика», «Электроника», «Дипломатия», «Картография». Один навык — одна **область умения**, а не задача и не инструмент. Навыки изначально не дробятся, поэтому и сливать их не нужно.

**Правило гранулярности (для LLM и для валидации):**
- Навык — это то, что человек назвал бы своим умением в резюме или в разговоре: «Биология», «Программирование», «Преподавание», «Фигурное катание», «Кулинария», «Вождение».
- **Не навык:** конкретная задача («домашка по матану» → «Математика»), инструмент или язык («Python», «R», «Julia» → «Программирование»), курс («BIO120» → «Биология»), разовое событие.
- Если сомневаешься между узким и широким — бери широкий. Узкое уходит в **специализацию** (перк, см. ниже).
- Целевой объём: у типичного человека 8–20 навыков за годы, а не сотни.

**Теги характеристик (как буквы у навыков в «Тёмном травнике»).** У каждого навыка есть **основная и вторичная характеристика**: «Программирование (Инт · Вол)», «Кулинария (Лов · Тво)», «Преподавание (Хар · Инт)», «Фигурное катание (Лов · Вын)», «Биология (Инт · Вос)». XP навыка идёт в основную характеристику с весом 2/3 и во вторичную с весом 1/3. Теги ставит LLM при создании навыка (всегда на уровне 9 конкретных характеристик), пользователь может поменять. Пока соответствующая общая характеристика не раскрыта, XP идёт в неё, а тег запоминается для раскрытия (2.4.4).

**Как появляются навыки:**
1. **Система предлагает** по повторяющейся активности. Активность, не попавшая ни в один навык, копится как кандидат. При **≥ 120 минутах фокуса минимум за 2 разных дня в пределах 14 дней** приходит предложение:
   ```
   [Система] Обнаружена повторяющаяся активность.
   Доступен навык: «Программирование» (Разум). Взять?   [Взять]  [Позже]  [Не предлагать]
   ```
   При взятии накопленный опыт засчитывается задним числом.
2. **Спящие навыки** — то, что человек уже умел до приложения. Указываются в онбординге или позже («я катаюсь 10 лет, 3 раза в неделю»). LLM оценивает прошлые часы практики и **целевой уровень** (по кривой 3.3: ~50 ч → ур. 17, ~200 ч → 32, ~500 ч → 49, ~1500 ч → 82). Спящий навык виден приглушённым с меткой «спит: ~82». Первая реальная активность его **пробуждает**: «[Система] Пробуждён спящий навык „Фигурное катание“». Дальше он получает **×5 XP**, пока не догонит целевой уровень, а потом растёт как обычно. Спящие навыки не занимают слот, пока не пробуждены. Это главный способ не начинать жизнь с нуля.
3. **По просьбе:** «хочу навык „Шахматы“» — Система создаёт кандидата и предлагает навык при первой активности.

**Специализации (перки).** На уровнях навыка 10, 25, 50, 75 и 100 Система предлагает выбрать **специализацию** из 2–3 вариантов, сгенерированных LLM по реальной истории активности в навыке. Например, «Биология» 25 → «Молекулярная биология» / «Генетика» / «Экология». Специализация — подпись к навыку и небольшой бонус (+10% XP к активностям, подходящим под неё), **не отдельный навык**. Так сохраняется обобщённость, но видно, в чём именно человек силён. Некоторые специализации требуют звёзд в характеристиках (например, «Научное руководство» у «Преподавания» — Харизма ≥ 15, а пока Дух не раскрыт — Дух ≥ 15).

Ранги навыка:

| Уровень навыка | Ранг |
|---|---|
| 1–9 | Новичок |
| 10–24 | Ученик |
| 25–49 | Подмастерье |
| 50–74 | Специалист |
| 75–99 | Эксперт |
| 100+ | Мастер |

### 2.3 Слоты навыков

Как в «Тёмном травнике», навыки делятся на **основные** и **второстепенные** слоты:

- **Основные:** 4 на старте, +1 на уровнях персонажа 10, 25, 50, 75, 100 (максимум 9). Получают полный XP и определяют класс.
- **Второстепенные:** 6 на старте, +1 на каждом 10-м уровне (максимум 16). Получают полный XP навыка, но их XP идёт в характеристики с коэффициентом 0.5, а на класс они не влияют.
- Навык можно переложить между основными и второстепенными раз в 7 дней на слот.
- Если слоты заняты, новый навык можно отложить или заменить им старый. Заменённый уходит в **архив** со всей историей и при возвращении сохраняет уровень.
- Активность вне навыков всё равно даёт XP персонажа и копится в кандидатах.

### 2.4 Характеристики: общие и раскрытие

Никакого дерева и выбора веток. Список характеристик плоский: сначала три общие, позже каждая **может** раскрыться в три конкретные — но только если человек реально в неё вкладывался.

**Общие характеристики (у всех с первого дня):** Тело · Разум · Дух.

**Во что они раскрываются (фиксированно):**

| Общая | Раскрывается в | Что качает (примеры навыков) |
|---|---|---|
| Тело | **Сила** | атлетика, тяжёлый физический труд, силовой спорт |
| Тело | **Ловкость** | спорт с техникой, танцы, фигурное катание, инструменты, ремонт руками, кулинария, лабораторная техника |
| Тело | **Выносливость** | смены на ногах, кардио, долгие нагрузки. **Увеличивает максимум HP** |
| Разум | **Интеллект** | учёба, наука, программирование, языки, анализ |
| Разум | **Восприятие** | вождение, диагностика, наблюдения, контроль качества, рисование с натуры |
| Разум | **Воля** | дисциплина и фокус: длинные сессии, тяжёлые задачи, регулярность |
| Дух | **Харизма** | преподавание, выступления, переговоры, торговля, лидерство |
| Дух | **Эмпатия** | психология, медицинский уход, воспитание, поддержка людей |
| Дух | **Творчество** | искусство, музыка, тексты, дизайн, изобретательство |

Список — конфиг `attributes.json`. Дальше характеристики **не дробятся**: вся узость уходит в специализации навыков (2.2).

#### 2.4.1 Старт: оценка Системы

- Все общие характеристики начинаются с **базы 10**.
- По опроснику и спящим навыкам (2.5) LLM даёт **бонус оценки**: от 0 до +6 на каждую общую характеристику, в сумме не больше +10. Например, «катаюсь 10 лет, учусь на биолога, преподаю физику» → Тело 12, Разум 15, Дух 13.
- Это LitRPG-момент: экран «[Система] Оценка персонажа завершена» с появлением трёх значений по одному.
- LLM обязан коротко объяснить каждое значение («Разум 15: учёба + 2 года программирования»), чтобы оценка не выглядела случайной.

#### 2.4.2 Калибровка: перекинуть очки

- После оценки у пользователя есть **5 очков калибровки** и **7 дней**, чтобы перенести их между общими характеристиками («я сильнее в Духе, чем решила Система»).
- Сумма сохраняется. Ни одна характеристика не может опуститься ниже 10 или подняться выше 18.
- Через 7 дней (или по кнопке «Готово») значения фиксируются, неиспользованные очки сгорают.

#### 2.4.3 Рост: звёзды и очки от долгого использования

- XP характеристик приходит из XP навыков по тегам (основная 2/3, вторичная 1/3; второстепенные слоты ×0.5) и из активности без навыка (по тегам классификатора).
- **10 звёзд = +1 очко характеристики.** Звезда — частое маленькое событие (1/10 порога), очко — редкое и большое.
- **«Долгое использование» буквально:** для +1 очка нужен не только XP, но и **минимум N разных дней** с активностью в этой характеристике (≥ 15 минут в день) с момента прошлого очка. N растёт со значением: 2 дня на 10–11, 3 на 12–13, … до 10 дней на 26+. Одним ночным марафоном очко не выбить.
- Формулы — в 3.4.

#### 2.4.4 Раскрытие (только по заслугам, только по согласию)

Пока характеристика общая, весь её XP копится в ней. Но каждая порция XP **тихо помечается** конкретной характеристикой, в которую она пошла бы после раскрытия (по тегам навыков: «Фигурное катание (Лов · Вын)» → Ловкость 2/3, Выносливость 1/3). Пользователь этого не видит, Системе это нужно для честного раскрытия.

**Условия, при которых Система *предлагает* раскрыть общую характеристику (все сразу):**
1. Уровень персонажа **≥ 20** (≈ 3 месяца активной жизни: достаточно истории, чтобы раскрытие было честным).
2. С момента регистрации в эту общую характеристику пришло **≥ 6 000 XP** (в среднем ~1 час в день основной активности в течение 3 месяцев).
3. Минимум **30 разных дней** с активностью в ней.

Если условия не выполнены, характеристика **остаётся общей сколько угодно**. Никакого принудительного раскрытия: если человек не качает Тело по отдельности на Силу, Выносливость и Ловкость, то и раскладывать нечего. Количество характеристик у каждого своё — от 3 до 9.

**Предложение:**
```
[Система] Разум готов к раскрытию: Интеллект · Восприятие · Воля.
Раскрыть?   [Раскрыть]  [Не сейчас]
```
Можно отказаться и раскрыть позже в любой момент, пока условия выполнены. Отказ ничего не стоит.

**Расчёт значений при раскрытии** (среднее значение сохраняется, видны сильные стороны):

```
R  = значение общей характеристики
E  = R − 10                       // сколько набрано сверх базы
s_i = доля помеченного XP, ушедшего в i-ю часть (сумма = 1)
child_i = max(10, R + round(0.5 × E × (3 × s_i − 1)))
```

Пример: Разум 18, доли Интеллект 55% / Воля 30% / Восприятие 15% → **Интеллект 21 · Воля 18 · Восприятие 16**.

- Остаток XP общей характеристики (прогресс к следующей звезде) делится между частями по тем же долям.
- После раскрытия даётся **2 очка калибровки** на 7 дней для переброса между тремя новыми характеристиками (если, например, последние недели была сессия и всё ушло в учёбу). Ограничения: не ниже 10, не выше `max(child) + 2`.
- Раскрытие **необратимо**. Перед подтверждением показать превью значений.
- Отдельный торжественный экран: общая карточка разделяется на три с анимацией.

#### 2.4.5 Пока характеристика общая

Всё, что ссылается на конкретную характеристику, берёт значение её общей характеристики:
- максимум HP считается от Выносливости, а пока Тело не раскрыто — от Тела;
- требование специализации «Харизма ≥ 15» засчитывается Духом ≥ 15;
- теги навыков отображаются по текущему состоянию: «Программирование (Разум)» до раскрытия Разума, «Программирование (Инт · Вол)» после.

#### 2.4.6 Что дают характеристики

1. +2% XP навыкам, у которых эта характеристика основная, за каждое очко выше 10 (максимум +30%).
2. Выносливость (или Тело) увеличивает максимум HP.
3. Характеристики вместе с основными навыками определяют класс (2.7) и открывают некоторые специализации и титулы.
4. Свободных очков за уровни **нет**: характеристики растут только от реальной активности, кроме калибровки на старте и после раскрытия.

### 2.5 Онбординг: опросник и спящие навыки

Опросник **не выбирает набор характеристик** (у всех одинаковые Тело, Разум, Дух). Он нужен, чтобы найти спящие навыки, дать стартовую оценку характеристик (2.4.1), предложить стартовые навыки и задать тон. 5 экранов, ответы в основном чипами, любой шаг можно пропустить.

1. **Возраст** (диапазоны): 13–15, 16–17, 18–24, 25–34, 35–49, 50–64, 65+. Влияет на тон текстов и ограничения (11.2).
2. **Чем ты сейчас в основном занят(а)?** (можно несколько): учусь в школе / учусь в колледже или университете / работаю / своё дело / спорт профессионально / дома с детьми или ухаживаю за близкими / на пенсии / ищу работу или себя.
3. **Сфера** (с поиском, можно несколько): группы из таблицы ниже + «другое» со свободным вводом.
4. **Что ты уже умеешь?** Свободный текст или голос: «катаюсь 10 лет, 3 раза в неделю; программирую 2 года; преподаю физику». LLM превращает это в **спящие навыки** с оценкой часов и целевого уровня. Пользователь видит список и правит.
5. **Что хочешь прокачать?** (до 3 целей): здоровье и тело, знания, карьера, творчество, отношения, спокойствие, дисциплина, своё дело. Влияет на подсказки Системы и первые недельные задания.

### 2.6 HP (Здоровье)

HP — полоска состояния, которая есть у каждого персонажа независимо от выбранных характеристик. Она показывает, **в каком ты сейчас состоянии**, а не сколько сделано.

- **Максимум HP:** `HP_max = 100 + 10 × (Выносливость − 10) + 2 × (уровень − 1)`; пока Тело не раскрыто — вместо Выносливости берётся Тело.
- **Утро:** HP восстанавливается по сну из чек-ина или по вопросу «как спалось?»: 7–9 часов → 100% максимума; 6 часов → 80%; 5 часов → 60%; меньше 5 → 45%. Если данных нет — 90%.
- **В течение дня:** тяжёлая нагрузка снижает HP: −4% за каждые 60 минут с intensity ≥ 1.3, −10% если за день больше 10 часов фокуса. Отдых, прогулки, хобби, общение с близкими восстанавливают: +5% за каждые 30 минут, максимум +30% за день.
- **Самочувствие:** в чек-ине — 5 смайликов «как ты себя чувствуешь?» и переключатель «заболел(а)». Болезнь — статус-эффект «Недомогание»: максимум HP −30% до отметки «выздоровел(а)».
- **Статус-эффекты** (LitRPG-баффы/дебаффы), показываются иконками у полоски: «Недосып» (сон < 6 ч), «Перегруз» (> 10 ч фокуса), «Недомогание», «Восстановление» (после дня отдыха, бафф: +10% XP на следующий день), «Второе дыхание» (возвращение после перерыва).
- **HP никогда ничего не отнимает.** Не уменьшает XP, не убивает персонажа, не сбрасывает уровни. При HP < 30% Система мягко советует отдых, а активности отдыха дают двойное восстановление.
- Значения конфигурируемы, все — в `lib/game/config.ts`.

### 2.7 Классы и титулы

- **Класс не выбирается, а вырастает** из распределения XP по доменам и характеристикам (пересчёт раз в неделю). Как в «Level Up» Сугралинова, до 10 уровня класс «не определён», и его открытие на 10 уровне — отдельное событие. Класс считается по основным навыкам и двум самым развитым характеристикам (общим или раскрытым — какие есть сейчас); раскрытие для класса не требуется. Примеры: Интеллект + Восприятие в науке → «Исследователь»; Интеллект + Харизма → «Наставник»; Интеллект (Логика) + Творчество в коде → «Инженер»; Сила + Выносливость → «Титан»; Ловкость + Восприятие → «Мастеровой»; Эмпатия + Харизма → «Целитель душ»; Восприятие + Выносливость → «Странник». Таблица классов — конфиг (JSON), 30–40 штук, минимум 2 «своих» класса у каждой группы из 2.5, плюс гибриды из двух топ-доменов: «Биоинформатик-исследователь».
- **Нет иерархии профессий.** Классы и титулы не должны звучать так, будто умственный труд «выше» физического или наоборот. Никакого «уровня социальной значимости»: уровень показывает прогресс человека относительно себя, а не его ценность.
- **Титулы/достижения** — конфиг правил, проверяется после каждого подтверждения записей. Примеры:
  - «Пожиратель статей» — 25 записей с навыком «Чтение научных статей»
  - «Исследователь миров» — 3 новых навыка за 30 дней
  - «Многостаночник» — 5 разных доменов за один день
  - «Первая кровь» — первая подтверждённая запись
  - «Возвращение» — запись после перерыва ≥ 7 дней (возвращение поощряется, а не наказывается)
- Один титул можно «носить» — он отображается под игровым именем.

### 2.8 Системные сообщения

Главная фишка ощущения LitRPG. После подтверждения записей показывается последовательность сообщений в стиле «окна Системы»:

```
[Система] Получено опыта: 412
[Система] Навык «Анализ белковых интерфейсов» повышен: 6 → 7
[Система] Обнаружена повторяющаяся активность. Доступен навык: «Научная работа». Взять?
[Система] Уровень персонажа повышен: 11 → 12. Открыт второстепенный слот навыка!
[Система] Разум: получена звезда (7/10 до +1 очка)
[Система] Получен титул: «Пожиратель статей»
[Система] HP: 64/120. Статус: «Перегруз». Рекомендуется отдых.
```

Новая звезда характеристики — редкое событие, у неё отдельная, более торжественная анимация, чем у повышения навыка. +1 очко характеристики и раскрытие — отдельные экраны: «Разум повышен: 17 → 18», «Разум раскрыт: Интеллект 21 · Воля 18 · Восприятие 16». Анимация: строки появляются по одной, лёгкий звук (выключаемый), level-up персонажа — отдельный экран-вспышка.

## 3. Математика

Все функции живут в `lib/game/formulas.ts`, версия — `FORMULA_VERSION = 1`. Константы вынести в `lib/game/config.ts`. 1 XP ≈ 1 минута фокуса обычной интенсивности.

### 3.1 XP записи

```
XP_entry = focus_minutes × k_intensity × k_novelty
```

- `focus_minutes` — оценка человека, сколько он реально был сосредоточен, **а не** разница между первым и последним сообщением.
- `k_intensity`: 0.5 (фоном/легко), 1.0 (обычно), 1.3 (тяжело), 1.6 (на пределе).
- `k_novelty`: 0.9 (совсем механическое повторение), 1.0 (обычно, **включая привычную работу по своей профессии**), 1.2 (много нового).

**Справедливость между профессиями:** час честных усилий грузчика, врача, школьника и учёного даёт примерно одинаковый базовый XP. Физическая тяжесть учитывается через `k_intensity` так же, как умственная. Новизна влияет слабо (0.9–1.2), чтобы обучение не было «дороже» работы. Тест: 8-часовая смена грузчика и 8-часовой учебный день студента при одинаковых intensity и novelty дают XP персонажа в пределах ±10% друг от друга (учебный день, как обычно, разбит на несколько навыков).

Распределение по навыкам: `XP_skill = XP_entry × share_skill × k_diminishing × k_attr_bonus × k_sleeping`.

- `share_skill` — доли навыков в записи, сумма = 1.
- `k_diminishing` — убывающая отдача **на навык в календарный день**: первые 180 минут ×1.0, следующие 120 минут ×0.7, дальше ×0.4. Защита от «10 часов одного и того же».
- **Исключение для рабочих смен:** навык с флагом `is_work_shift` (смена грузчика, дежурство медсестры, смена в кафе) имеет порог 480 минут ×1.0, затем ×0.7. Иначе люди с длинными однотипными сменами систематически получали бы меньше. Флаг ставит LLM, пользователь может поменять.
- `k_attr_bonus` = 1 + 0.02 × (значение основной характеристики навыка − 10), от 1.0 до 1.3 (пока характеристика общая — берётся общая).
- `k_sleeping` = 5, пока пробуждённый спящий навык не догнал целевой уровень, иначе 1. Действует только на XP навыка, не на XP персонажа и характеристик.

XP персонажа = `XP_entry` (без убывающей отдачи и бонусов, чтобы уровень персонажа отражал честное время).

Валидация дня: если сумма `focus_minutes` за день > 16 часов, показать мягкое предупреждение («Похоже, тут есть пересечения — проверить?»), но не блокировать.

### 3.2 Уровень персонажа

```
xp_to_next(L) = round(100 × L^1.2)
```

Накопительный XP (посчитано). Ориентир — активный день ≈ 360 XP (≈ 6 часов полезной активности):

| Уровень | Накоплено XP | ≈ дней активной жизни |
|---|---|---|
| 2 | 100 | первый же день |
| 5 | 1 232 | ~3 |
| 10 | 6 424 | ~2.5 недели |
| 25 | 51 718 | ~5 месяцев |
| 50 | 243 047 | ~1.9 года |
| 100 | 1 129 232 | ~8.5 лет |

### 3.3 Уровень навыка (быстро)

```
skill_xp_to_next(n) = round(15 × n^1.15)
```

Без жёсткого потолка; после 100 ранг «Мастер» сохраняется. Накопительно (в минутах фокуса в этом навыке, посчитано):

| Уровень навыка | Часов практики |
|---|---|
| 2 | 0.25 |
| 5 | ~3 |
| 10 | ~15 |
| 25 | ~113 |
| 50 | ~510 |
| 75 | ~1 230 |
| 100 | ~2 300 |

Первые уровни навыка падают за один-два вечера, потом растягиваются — как в книгах.

### 3.4 Характеристики: звёзды, очки, раскрытие

```
xp_to_next_point(v) = round(600 × (v − 9)^1.2)          // v → v+1; звезда = 1/10 этого
days_required(v)    = min(10, 2 + floor((v − 10) / 2))  // разных активных дней с прошлого очка
// активный день для характеристики = ≥ 15 минут фокуса с её тегом
```

Посчитано (скрипт в Приложении B):

| Переход | XP за очко | XP за звезду | Нужно разных дней |
|---|---|---|---|
| 10 → 11 | 600 | 60 | 2 |
| 12 → 13 | 2 242 | 224 | 3 |
| 14 → 15 | 4 139 | 414 | 4 |
| 16 → 17 | 6 198 | 620 | 5 |
| 18 → 19 | 8 380 | 838 | 6 |
| 20 → 21 | 10 662 | 1 066 | 7 |
| 25 → 26 | 16 715 | 1 672 | 9 |

Уровень 20, с которого возможно раскрытие, — 31 296 XP, то есть **~87 дней** при ~6 часах полезной активности в день (~2.9 месяца).

Модельный профиль студентки-исследовательницы: оценка на старте Тело 12, Разум 15, Дух 13; в характеристики уходит Разум ~240 XP в день ежедневно, Дух ~80 XP в среднем (5 дней в неделю), Тело ~40 XP в среднем, но активность только 2 дня в неделю. Симуляция до 20 уровня:

| Характеристика | Старт → к ур. 20 | XP с регистрации | Активных дней | Раскрытие на ур. 20 |
|---|---|---|---|---|
| Разум | 15 → 18 (очки на 22, 48 и 78 день) | ~20 900 | 87 | предлагается |
| Дух | 13 → 14 | ~7 000 | ~62 | предлагается |
| Тело | 12 → 13 | ~3 500 | ~24 | **нет**, остаётся общим (при той же активности условия выполнятся примерно к ур. 26) |

Для главной характеристики это примерно +1 очко в месяц и звезда раз в несколько дней — редко, но заметно. Пороги раскрытия (уровень 20, 6 000 XP, 30 дней) вынести в конфиг.

### 3.6 Леджер и пересчёт

Каждое начисление пишется в `xp_events` (entry_id, target_type [character|skill|candidate|attribute], target_id, amount, multipliers JSON, formula_version). Агрегаты (уровни, навыки, характеристики) — кэш, который полностью пересчитывается командой `pnpm game:recompute` из `activity_entries`. Это обязательное требование: баланс будет меняться, а задним числом засчитанные кандидаты, пробуждение спящих навыков и уточнение тегов до веток опираются на этот пересчёт.

## 4. Источники данных

Три канала. Все создают одну и ту же сущность `activity_entry` с полем `source`.

### 4.1 ИИ-агент через MCP (Claude, ChatGPT)

Приложение поднимает **remote MCP server** (раздел 7). Пользователь добавляет его как custom connector в Claude (claude.ai / desktop / mobile) или как app в ChatGPT (developer mode). После этого ИИ-агент может:

- **По ходу разговора** залогать активность, если пользователь явно занимался чем-то (разбирал статью, учил тему, писал код).
- **В конце дня по команде** «залогай день»: агент просматривает сегодняшние разговоры (в Claude — через встроенный поиск по прошлым чатам, если он включён), оценивает реальное фокусное время, сначала показывает пользователю список, а после «ок» отправляет его одним вызовом `log_activities`.

Важно для реализма:
- Агент **не видит** всё автоматически: коннектор должен быть включён, и модель сама решает, когда вызывать инструмент. Поэтому основной надёжный сценарий — вечерняя команда, а логирование «по ходу» — бонус.
- Записи от ИИ создаются со статусом `draft`, если в настройках не включено автоподтверждение.
- **Правило авторства:** если основную работу сделал ИИ (написал код, сделал перевод), пользователь получает XP за разбор и понимание, а не за «написание». Это прописано в инструкциях MCP-сервера.

### 4.2 Вечерний чек-ин (голос или текст)

- В заданное пользователем время (своё для каждого: кто-то заканчивает в 20:00, кто-то в 02:00) приходит push-уведомление: «Отчёт для Системы готов к приёму».
- Экран чек-ина: большая кнопка микрофона и текстовое поле. Пользователь рассказывает день своими словами: что делал, сколько примерно, насколько тяжело, сколько нового.
- **MVP:** текстовое поле + встроенная диктовка клавиатуры телефона (ноль затрат и уже хорошо работает с русским). **Фаза 3:** запись аудио в приложении (MediaRecorder) → speech-to-text API с хорошим русским (выбери и сравни 2 варианта по цене и качеству, предложи мне).
- Текст уходит в LLM (Anthropic API, structured output по JSON-схеме из раздела 8). В промпт подаются: список существующих навыков пользователя и **уже залогированные за этот день записи** (из MCP и вручную), чтобы не было дублей.
- Результат — список черновых карточек. Каждую можно: подтвердить, поправить время/интенсивность/навыки слайдерами и чипами, удалить, разделить на две. Кнопка «Подтвердить всё».
- Если запись совпадает с уже существующей (например, Claude днём залогал «PRODIGY, 1.5 ч», а в голосе сказано «посидела над белками часа два»), LLM возвращает `merge_with: <entry_id>` с предложенной правкой, а не создаёт дубль.

### 4.3 Ручной лог и таймер

- Быстрое добавление: «+» → навык (поиск/чипы недавних) → длительность → интенсивность. 3 тапа.
- Таймер: старт/стоп для текущей активности, в конце — экран подтверждения с вопросом «сколько из этого времени ты реально была в фокусе?» (по умолчанию 85%).

## 5. Экраны и UX

1. **Status (главный)** — «окно статуса»: аватар, игровое имя, титул, класс, уровень и полоса XP до следующего, полоска HP со статус-эффектами, характеристики (3–9 карточек: значение, 10 звёзд прогресса до следующего очка, у общих — индикатор готовности к раскрытию), основные навыки с тегами, XP за сегодня, ожидающие предложения навыков от Системы. Внизу кнопка «Отчёт за день».
2. **Skills** — список навыков, сгруппированный по доменам, сортировка по уровню и по недавней активности, у каждого: уровень, ранг, прогресс-бар, часы за всё время, спарклайн за 30 дней. Счётчик слотов «занято N из M», архив навыков, кандидаты в навыки с прогрессом до предложения.
3. **Journal** — лента дней. День = карточки записей с источником (иконка Claude / ChatGPT / голос / ручная). Черновики подсвечены.
4. **Check-in** — см. 4.2.
5. **Chronicle (Хроника)** — главный антидот от «я никуда не двигаюсь»:
   - «Ты месяц назад vs сейчас»: уровень, характеристики, топ-навыки.
   - Итоги недели/месяца: часы по доменам, новые навыки, повышенные ранги, полученные титулы.
   - Счётчики за всё время: «312 часов учёбы», «48 разобранных статей», «94 часа преподавания».
   - Heatmap активности (как GitHub contributions), но без красных пропусков — пустые дни просто нейтральные.
   - Еженедельное короткое «письмо от Системы» (генерирует LLM по данным недели, тон тёплый и конкретный, без лести и пустых похвал).
6. **Character** — редактор персонажа (раздел 6), игровое имя, выбор титула.
7. **Settings** — время чек-ина + часовой пояс, каналы уведомлений, подключение ИИ-агентов (инструкции + токен/OAuth), автоподтверждение записей от ИИ (вкл/выкл), спящие навыки (добавить / поправить оценку опыта), источник данных о сне для HP, язык, экспорт данных (JSON + CSV), удаление аккаунта.
8. **Onboarding** — опросник из раздела 2.5 (5 коротких экранов) → экран «Твои спящие навыки» (список из шага 4, можно поправить оценку опыта) → стартовые навыки (Система предлагает по группе, пользователь берёт нужные в основные и второстепенные слоты) → «Оценка персонажа» (Тело, Разум, Дух с объяснениями) и калибровка 5 очков (2.4.1–2.4.2) → имя персонажа и внешний вид → время чек-ина и подключение Claude/ChatGPT (можно пропустить). Весь онбординг ≤ 3 минут, любой шаг можно пропустить и вернуться позже.

## 6. Визуальный стиль и персонаж

### 6.1 Интерфейс

- Минимализм, но «дорого»: тёмная тема по умолчанию (светлая — опция), глубокий почти чёрный фон с лёгким сине-фиолетовым оттенком.
- Панели в стиле «системного окна»: полупрозрачные (glassmorphism без перебора), тонкая светящаяся рамка 1px, мягкое внешнее свечение у активных элементов.
- Каждой характеристике — свой акцентный цвет, у HP — свой (тёплый красный), проверенный на контраст в обеих темах (WCAG AA).
- Типографика: чистый гротеск для UI (Inter или Geist) + моноширинный для цифр и системных сообщений (JetBrains Mono или Geist Mono). Цифры — tabular-nums.
- Анимации через Framer Motion: плавное заполнение полос XP, появление системных сообщений построчно, отдельная сцена level-up. Уважать `prefers-reduced-motion`.
- Mobile-first: всё удобно одной рукой, нижняя навигация из 4–5 пунктов.

### 6.2 Персонаж (не мультяшный, ближе к стилю аниме-RPG)

Референс по ощущению — 3D-персонажи аниме-RPG с cel-shading (уровня Genshin Impact). **Никаких ассетов, моделей и узнаваемых персонажей из существующих игр** — только общий стиль.

Реалистичный путь:

- **Формат VRM** (открытый стандарт для 3D-гуманоидных аватаров), рендер в браузере через `three` + `@pixiv/three-vrm` + `@react-three/fiber`.
- **Фаза 4a:** 4–6 базовых моделей, сделанных в **VRoid Studio** (бесплатный редактор аниме-персонажей с экспортом в VRM) или взятых с явной лицензией, разрешающей такое использование (проверить и записать лицензию каждой модели в `assets/avatars/LICENSES.md`). В приложении: выбор базы, смена цвета волос/глаз/одежды через параметры материалов, idle-анимация (дыхание, моргание, лёгкие покачивания), поворот пальцем.
- **Фаза 4b:** импорт собственного `.vrm` — пользователь делает персонажа в VRoid Studio как угодно детально и загружает. Валидация файла (размер ≤ 30 МБ, корректный VRM 0.x/1.0), хранение в Supabase Storage.
- **Фаза 4c (позже):** косметика за уровни — аура/частицы вокруг персонажа на 25/50/100, рамки портрета, позы для level-up.
- Fallback для слабых устройств: статичный рендер-портрет (snapshot canvas → PNG), кэшируется после первой загрузки.
- **В MVP (фазы 1–3)** вместо 3D — стильный 2D-портрет-заглушка (силуэт + цвет класса), чтобы 3D не блокировал запуск.

Полноценный конструктор персонажа внутри приложения (как в играх) — огромный объём работы, в этот план не входит.

## 7. MCP server

### 7.1 Транспорт и размещение

- Endpoint: `https://<domain>/api/mcp`, transport — **Streamable HTTP**, официальный TypeScript SDK `@modelcontextprotocol/sdk`.
- Стандартный порт 443 (Claude не подключается к URL с нестандартным портом).

### 7.2 Аутентификация

- **Фаза 2 (только для меня):** персональный API-токен, который генерируется в Settings и передаётся в заголовке запроса (Claude умеет отправлять фиксированные заголовки для custom connector). Токен хранится хэшем, его можно отозвать.
- **Фаза 5 (для всех пользователей):** OAuth 2.1 по актуальной спецификации MCP Authorization (PKCE, protected resource metadata, authorization server metadata, dynamic client registration и/или Client ID Metadata Documents — проверь, что сейчас поддерживают Claude и ChatGPT). Используй поддерживаемую библиотеку, не пиши криптографию сама. Обязательно `offline_access` / refresh tokens, иначе ChatGPT будет терять доступ.

### 7.3 Инструменты

Все инструменты работают только с данными аутентифицированного пользователя.

| Tool | Назначение |
|---|---|
| `get_status` | Уровень, XP до следующего, HP и статус-эффекты, характеристики, топ-навыки, XP за сегодня. Чтобы агент мог сказать «тебе 40 XP до 12 уровня». |
| `list_skills` | Навыки пользователя (id, name, path, level), опционально с фильтром `query`. **Агент обязан вызвать его перед логированием**, чтобы использовать существующие навыки. |
| `get_day` | Записи за дату (по умолчанию сегодня в часовом поясе пользователя). Чтобы не дублировать. |
| `log_activities` | Массив записей (схема ниже). Создаёт черновики (или подтверждённые записи, если включено автоподтверждение). Возвращает созданные id и итоговые системные сообщения. |
| `update_activity` | Правка записи, созданной этим же агентом, пока она в статусе draft. |
| `delete_activity` | Удаление черновика, созданного этим агентом. |
| `request_skill` | Попросить Систему о навыке (название обобщённого уровня по правилу 2.2, теги характеристик). Сервер проверяет похожие (`possible_duplicates`) и создаёт **кандидата/предложение**: взять навык пользователь решает сам в приложении, агент навыки не берёт. |

Схема элемента `log_activities`:

```json
{
  "date": "2026-11-25",
  "description": "Разбор статьи о PRODIGY и планирование OOD-аудита",
  "focus_minutes": 105,
  "intensity": 1.3,
  "novelty": 1.25,
  "skills": [
    { "skill_id": "uuid-или-null", "activity_cluster": null, "share": 0.6 },
    { "skill_id": null, "activity_cluster": "структурная биоинформатика", "share": 0.4 }
  ],
  "confidence": 0.7,
  "evidence": "Обсуждение в чате ~11:00–16:00 с перерывами; пользователь сказал, что параллельно слушала лекцию",
  "client_ref": "строка для идемпотентности"
}
```

`client_ref` + `date` — ключ идемпотентности: повторный вызов не создаёт дубль.

### 7.4 Server instructions (поле `instructions` MCP-сервера)

Первые ~500 символов должны быть самодостаточными. Текст:

```
Status — трекер прокачки персонажа по реальной активности пользователя.
Логируй только то, чем пользователь реально занимался сам. Оценивай ФОКУСНОЕ время,
а не время от первого до последнего сообщения: люди делают несколько дел параллельно.
Если не уверен во времени, спроси пользователя или поставь confidence < 0.5.
Перед log_activities всегда вызывай list_skills и get_day, чтобы использовать
существующие навыки и не создавать дубли. Если основную работу сделал ты (ИИ),
пользователь получает XP за разбор и понимание, а не за выполнение: снижай focus_minutes
и intensity соответственно. Перед вечерним массовым логированием покажи пользователю
список и дождись подтверждения. Не логируй личные разговоры, здоровье и переживания
как «навыки», если пользователь сам об этом не попросил.
```

Описания каждого инструмента — короткие, с примерами корректного вызова.

### 7.5 Тестирование

MCP Inspector + интеграционные тесты: вызов каждого инструмента, неверный токен, чужие данные, идемпотентность, лимит запросов (rate limit на пользователя, например 60 вызовов в минуту).

## 8. LLM-разбор вечернего отчёта

- Модель: Claude через Anthropic API, вызов только с сервера (ключ не уходит на клиент). Модель указать в конфиге, а не в коде.
- Structured output через tool use с JSON-схемой:

```json
{
  "entries": [
    {
      "description": "string",
      "focus_minutes": 0,
      "intensity": 0.5,
      "novelty": 1.0,
      "skills": [{ "skill_id": "string|null", "activity_cluster": "string|null", "share": 0.0 }],
      "attribute_tags": { "primary": "intellect", "secondary": "perception" },
      "merge_with": "entry_id|null",
      "confidence": 0.0,
      "quote": "фрагмент отчёта, из которого это следует"
    }
  ],
  "new_clusters": [
    { "cluster": "string", "suggested_skill_name": "string", "parent_path": "string",
      "attribute_tags": { "primary": "intellect", "secondary": "will" }, "is_work_shift": false }
  ],
  "wellbeing": { "sleep_hours": 7.5, "mood_1_5": 4, "sick": false },
  "clarifying_questions": ["string"]
}
```

- Правила в системном промпте: не выдумывать активности, которых нет в тексте; если время не названо — оценить по контексту и поставить низкий confidence; бытовые дела (поела, доехала) не логировать, если пользователь явно не считает их значимыми; отдых и хобби логировать как активность восстановления (для HP) и, если они регулярные, как обычные навыки (чтение, прогулки, музыка); самочувствие и сон — только в `wellbeing`, если пользователь сам о них сказал; максимум 3 уточняющих вопроса.
- Серверная валидация ответа (zod): доли суммируются в 1 (иначе нормализовать), диапазоны коэффициентов, `focus_minutes` от 1 до 960.

**Тестовая фикстура (обязательный e2e-кейс):**

> «Сегодня встала в девять, два часа слушала лекцию по биологии, параллельно разбиралась с Claude в новом проекте по белкам — по чату это часов пять, но реально я уделила белкам часа полтора-два. Потом решала домашку по матану около часа, было тяжело. Вечером час занималась с учеником физикой. Потом немного отдохнула, почитала книжку.»

Ожидаемо: 5 черновиков — лекция → навык «Биология» (~120 мин), проект по белкам → «Научная работа» (~105 мин, а не 300), домашка по матану → «Математика» (~60 мин, intensity 1.3), репетиторство → «Преподавание» (~60 мин), чтение для удовольствия → «Чтение» или кандидат (восстановление HP). Ни один навык не должен называться «BIO120», «домашка» или «PRODIGY». `sleep_hours` = `null`: известно только время подъёма, время отхода ко сну не названо, выдумывать нельзя. Если днём Claude уже залогал белки через MCP, то вместо новой записи — `merge_with`.

## 11. Безопасность и приватность

- RLS: пользователь видит только свои строки. Тест, проверяющий это для каждой таблицы.
- Все LLM-вызовы на сервере. В LLM уходит минимум данных: текст отчёта, названия навыков, записи дня. Без email и id аккаунта.
- Аудио (фаза 3) удаляется после транскрипции по умолчанию; хранение — опция.
- Экспорт всех данных одним архивом и удаление аккаунта со всеми данными.
- Rate limiting на API, MCP и LLM-эндпоинты. Месячный лимит LLM-вызовов на пользователя (конфиг), чтобы счёт за API не улетел.
- Ответы опросника (возраст, занятость) — тоже личные данные: храним только диапазоны, в LLM передаём только то, что нужно для подбора.
- Содержимое ответов MCP не должно включать инструкции, которые агент мог бы принять за команды (защита от prompt injection через пользовательские описания: экранировать/обрезать description в выдаче).

### 11.1 Тело и здоровье без вреда

- **Никакого XP за вес, калории, «сколько не ел(а)» или похудение.** Телесные характеристики качаются только от активности, а HP — от сна и восстановления. Если пользователь пишет о голодании, резком ограничении еды или тренировках через травму — LLM не начисляет за это XP и мягко не поощряет такую запись.
- Недосып не поощряется: никаких титулов и бонусов за работу по ночам или за ночи без сна.
- Убывающая отдача (3.1) и предупреждение о >16 часах в день остаются как защита от перегруза.

### 11.2 Возраст

- **На запуске — только 13+.** Регистрация младше 13 лет в США требует проверяемого согласия родителей по COPPA, в ЕС возраст цифрового согласия по GDPR — от 13 до 16 лет в зависимости от страны. Перед публичным запуском — консультация юриста по странам, где будет приложение (включая Канаду и Россию).
- **13–17:** в зависимости от страны может понадобиться согласие родителей; никаких публичных рейтингов и социальных функций с незнакомыми людьми; письма Системы и тексты — дружелюбные, без давления; ночные уведомления отключены (не позже 22:00 по умолчанию).
- **65+:** режим крупного шрифта и упор на голосовой ввод, предлагаются в онбординге автоматически (можно выключить).
- Возраст задаётся диапазоном, точную дату рождения не спрашиваем.

**Фаза 1 — MVP «для себя».** Онбординг (без 3D) с опросником и спящими навыками (2.5), общие характеристики, оценка, калибровка, звёзды и раскрытие (2.4), предложение навыков Системой, специализации и слоты (2.2–2.3), HP (2.6), ручной лог, экран Status, Skills, Journal, системные сообщения, чек-ин **текстом** (диктовка клавиатуры) с LLM-разбором и карточками-черновиками, тестовая фикстура из раздела 8 проходит.

**Фаза 2 — подключение ИИ-агента.** MCP server с токен-аутентификацией, все инструменты из 7.3, страница в Settings с пошаговой инструкцией подключения к Claude и ChatGPT, дедупликация MCP-записей и чек-ина.

**Фаза 3 — привычка.** PWA, web push, email fallback, cron чек-инов по локальному времени, запись голоса в приложении + speech-to-text, таймер, Chronicle (сравнения, итоги, heatmap, письмо Системы), титулы, классы.

**Фаза 4 — персонаж.** VRM-аватар (4a → 4b → 4c из раздела 6.2).

**Фаза 5 — для других людей.** OAuth 2.1 для MCP, лимиты, лендинг, экспорт/удаление, полировка, аналитика без трекинга личного содержимого.

**Фаза 6 — приложение.** Capacitor или Expo, нативные уведомления.

## 13. Критерии готовности MVP (фазы 1–2)

- Новый пользователь проходит онбординг и делает первую запись меньше чем за 3 минуты.
- Вечерний отчёт из раздела 8 превращается в разумные черновики, их правка и подтверждение занимают меньше минуты.
- Claude через custom connector может вызвать `get_status` и `log_activities`; запись появляется в Journal с иконкой Claude.
- Повторный вызов с тем же `client_ref` не создаёт дубль; запись из MCP и из чек-ина про одно и то же сливается.
- `pnpm game:recompute` пересчитывает все уровни из сырых записей и даёт тот же результат.
- Все тесты зелёные, Lighthouse mobile ≥ 90 по Performance и Accessibility на Status.

## Приложение A. Что добавить в настройки Claude со стороны пользователя

Чтобы «залогай день» работал стабильно, пользователь добавляет в свои инструкции Claude (Settings → Profile/preferences или инструкции проекта):

```
У меня подключён коннектор Status (трекер прокачки). Когда я пишу «залогай день»:
1) найди мои сегодняшние разговоры; 2) вызови list_skills и get_day;
3) составь список активностей с честной оценкой фокусного времени (не длительности чата)
и покажи его мне; 4) после моего «ок» вызови log_activities.
По ходу обычных разговоров логай активность, только если я сама прошу.
```

Последнюю строку можно поменять на «логай по ходу сам, если я явно над чем-то работаю».

## Приложение B. Скрипт баланса (`scripts/balance.py`)

Таблицы из 3.2–3.4 получены этим скриптом. Перенеси формулы в `lib/game/formulas.ts`, а скрипт оставь как эталон для тестов.

```python
import math

def xp_to_next_level(L): return round(100 * L**1.2)
def xp_to_next_point(v): return round(600 * (v - 9)**1.2)      # v -> v+1
def days_required(v): return min(10, 2 + (v - 10)//2)            # distinct active days per +1 point

def level_day(target, xp_per_day=360):
    cum = sum(xp_to_next_level(L) for L in range(1, target))
    return cum, cum / xp_per_day

def simulate(start, xp_per_day, active_days_per_week, days):
    """Returns list of (day, value, stars) at each point gain."""
    v, pool, act, events = start, 0.0, 0, []
    for d in range(1, days + 1):
        active = (d % 7) < active_days_per_week
        if active:
            pool += xp_per_day * 7 / active_days_per_week   # same weekly volume
            act += 1
        while pool >= xp_to_next_point(v) and act >= days_required(v):
            pool -= xp_to_next_point(v); v += 1; act = 0
            events.append((d, v))
    return v, events

print("== Уровень персонажа (360 XP/день) ==")
for L in (5, 10, 15, 20, 25, 30):
    cum, d = level_day(L); print(f"ур.{L}: {cum} XP, ~{d:.0f} дн (~{d/30.4:.1f} мес)")

print("\n== Очко характеристики: стоимость, звезда = 1/10, дней активности ==")
for v in (10, 11, 12, 14, 16, 18, 20, 25):
    print(f"{v}->{v+1}: {xp_to_next_point(v)} XP, звезда {xp_to_next_point(v)/10:.0f} XP, нужно дней {days_required(v)}")

_, d20 = level_day(20)
D = round(d20)
print(f"\n== Профиль, похожий на студентку-исследовательницу, до ур.20 (день {D}) ==")
profile = {"Разум": (15, 240, 7), "Дух": (13, 80, 5), "Тело": (12, 40, 2)}
for name, (start, xpd, adw) in profile.items():
    v, ev = simulate(start, xpd, adw, D)
    print(f"{name}: старт {start} -> {v} к дню {D}, заработано в приложении +{v-start}; очки на днях {[e[0] for e in ev]}")

print("\n== Эталоны для раскрытия: сколько очков набирает общая характеристика к ур.20 ==")
for xpd in (20, 40, 80, 150, 240):
    for start in (10, 12, 15):
        v, ev = simulate(start, xpd, 5, D)
        print(f"{xpd:>3} XP/день, старт {start}: +{v-start}")
```
