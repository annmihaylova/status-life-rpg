## 2. Что в SPEC противоречиво или не определено

Предлагаю решения, их можно поправить.

1. **Пересчёт требует журнала решений, а не только XP.** `pnpm game:recompute` не восстановит состояние только из `activity_entries`: результат зависит от решений пользователя (взяла навык, раскрыла характеристику, калибровка, перенос слота, выбор специализации, пробуждение). Предлагаю таблицу `game_decisions` (user_id, kind, payload, decided_at), и движок как чистая функция `replay(entries, decisions, config) → state`. Агрегаты в БД остаются кэшем.
2. **Порядок убывающей отдачи внутри дня.** Какая запись получает ×1.0, а какая ×0.7, зависит от порядка. Предлагаю сортировку по `started_at`, затем `created_at`. Тогда пересчёт детерминирован.
3. **novelty 1.25 в примере MCP (7.3)**, а в 3.1 допустимы 0.9 / 1.0 / 1.2. Предлагаю непрерывный диапазон 0.9–1.2 с обрезкой, intensity — 0.5–1.6.
4. **Навыки в примерах нарушают правило гранулярности 2.2:** «Анализ белковых интерфейсов» (2.8) и «Чтение научных статей» (титул «Пожиратель статей», 2.7). Предлагаю в примерах «Научная работа», а титул считать по 25 записям со специализацией или тегом «статьи».
5. **«Интеллект (Логика)» в 2.7.** Характеристики «Логика» нет. Класс «Инженер» = Интеллект + Творчество.
6. **«День отдыха» не определён** (бафф «Восстановление»). Предлагаю: за день < 120 минут фокуса вне активностей отдыха и ≥ 60 минут отдыха. Для этого у навыка или записи нужен флаг `is_rest`, он же нужен HP для восстановления (+5% за 30 минут).
7. **«Второе дыхание»:** эффект не задан. Предлагаю +10% XP персонажа в первый день после перерыва ≥ 7 дней, вместе с титулом «Возвращение».
8. **Вес XP характеристик для активности без навыка** не указан. Предлагаю ×0.5, как у второстепенных слотов.
9. **Drizzle и RLS.** Серверное подключение Drizzle к Postgres по умолчанию обходит RLS. Все пользовательские запросы пойдут через обёртку `withUser(userId, tx => …)`: `set local role authenticated` и `request.jwt.claims` в транзакции. Тогда RLS действует и на сервере, а тест RLS проверяет обе стороны.
10. **Статический заголовок для custom connector в Claude (7.2).** Не уверена, что Claude сейчас позволяет задать произвольный заголовок. Проверю по документации в начале фазы 2. Запасной вариант: сразу минимальный OAuth 2.1 через готовую библиотеку, то есть часть фазы 5 переедет в фазу 2.

## 3. Фазы

Каждая фаза заканчивается деплоем на Vercel, зелёным CI и обновлённым `CLAUDE.md`.

### Фаза 0 — фундамент
- pnpm (через corepack), Next.js App Router + TypeScript strict, Tailwind + shadcn/ui, next-intl (ru по умолчанию, en), ESLint + Prettier.
- Supabase: Auth (magic link + Google), Drizzle-схема всех таблиц раздела 10 плюс `game_decisions`, RLS-политики в миграциях, тест RLS на каждую таблицу. Локально — Supabase CLI в Docker (Docker установлен), прод — облачный проект.
- `lib/game/`: `config.ts`, `formulas.ts` (`FORMULA_VERSION = 1`): XP записи, убывающая отдача (включая `is_work_shift`), уровни персонажа и навыков, ранги, слоты, очки и звёзды характеристик, `days_required`, раскрытие, `computeHp`. Тесты сверяют таблицы выше и пример раскрытия, TS-порт `simulate` сверяется с выводом `balance.py`.
- GitHub Actions: lint, typecheck, vitest. Пустое приложение задеплоено на Vercel. `.env.example`.

### Фаза 1 — MVP «для себя» (три деплоя)
- **1a. Движок:** `replay()` по записям и решениям, леджер `xp_events`, `pnpm game:recompute` (тест: пересчёт = инкрементальный результат), кандидаты навыков (≥ 120 мин, ≥ 2 дня за 14 дней) с ретро-зачётом, спящие навыки (×5 до цели, с разбиением записи на границе), слоты и архив, звёзды, очки, раскрытие, калибровки, специализации, HP и статус-эффекты, генератор системных сообщений.
- **1b. Интерфейс:** онбординг (5 экранов → спящие навыки → стартовые навыки → оценка и калибровка → имя), Status, Skills, Journal, ручной лог за 3 тапа, системные сообщения с анимацией, 2D-портрет-заглушка. Конфиги `attributes.json`, `presets.json`, черновики классов и титулов (вопрос 14.5).
- **1c. Чек-ин текстом:** серверный вызов Anthropic API (модель в конфиге), structured output через tool use, zod-валидация и нормализация долей, карточки-черновики (подтвердить / поправить / разделить / удалить / «подтвердить всё»), `merge_with`. E2E на фикстуре из раздела 8, месячный лимит LLM-вызовов.

### Фаза 2 — ИИ-агент
MCP server на `/api/mcp` (Streamable HTTP, официальный SDK), токены в Settings (хэш, отзыв), все 7 инструментов, идемпотентность `client_ref + date`, rate limit 60/мин, экранирование описаний в ответах, инструкции подключения к Claude и ChatGPT, интеграционные тесты и MCP Inspector.

### Фаза 3 — привычка
PWA и service worker, web push (VAPID) с инструкцией для iOS, email-запасной канал (Resend), cron каждые 15 минут по локальному времени, таймер, запись голоса и speech-to-text (сравню 2 сервиса по цене и качеству русского), Chronicle (сравнения, итоги, heatmap, письмо Системы), титулы, классы.

### Фаза 4 — персонаж
VRM: 4a базовые модели и материалы с `LICENSES.md`, 4b импорт своего `.vrm`, 4c косметика. PNG-fallback.

### Фаза 5 — для других
OAuth 2.1 для MCP с refresh tokens, лимиты, лендинг, экспорт и удаление аккаунта, аналитика без содержимого.

### Фаза 6 — приложение
Capacitor или Expo — решаем после фазы 5.

## 4. Что нужно от тебя перед фазой 0

1. Одобрение плана и решений из раздела 2 (или правки).
2. **Supabase:** создать проект и вписать ключи в `.env.local` самой (я ключи никуда не ввожу). Список переменных будет в `.env.example`.
3. **Vercel:** подключить репозиторий к своему аккаунту.
4. **Google OAuth:** client ID/secret в Google Cloud Console — можно позже в фазе 0, magic link заработает без него.
5. Открытые вопросы 14.1–14.3 можно решить позже. По умолчанию: рабочее название Status, автоподтверждение выключено, продукт строго личный.
